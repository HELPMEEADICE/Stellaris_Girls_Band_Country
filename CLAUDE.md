## Repository type

This is a Stellaris mod. `descriptor.mod` declares it as a gameplay mod named `户山香澄的大少女乐团国Dev`, targeting Stellaris `v4.0.14`, with `replace_path = "music"`.

## Development commands

There is no repo-local build system, lint script, test runner, or single-test harness checked into this repository. No `README.md`, `CLAUDE.md`, Cursor rules, Copilot instructions, shell scripts, or package manifests are present.

Useful commands while editing:

- Check working tree: `git status`
- Review changes: `git diff`
- Check for whitespace / patch issues: `git diff --check`
- Search for an event / flag / effect ID: `git grep -n "bgbn_space_exploration\.1"`
- Search for country flags or scripted effects before renaming: `git grep -n "poppinparty\|create_ksm\|fix_paspal"`

Validation is manual in Stellaris. There is no automated way in this repo to run a single test; verification means loading the mod in-game and exercising the relevant event chain / authority / situation / archaeology content.

## High-level architecture

The mod is mostly data-driven Paradox script. The core gameplay loop is spread across `common/`, `events/`, `localisation/`, and `gfx/`.

### Main entrypoints

- `common/on_actions/*.txt` wires the mod into Stellaris lifecycle hooks.
- `common/on_actions/00_bgbn_start_events.txt` starts the mod’s initialization on `on_game_start_country` and runs a monthly portrait/leader repair event.
- `common/on_actions/01_bgbn_age_and_leaders_set.txt` triggers the main startup event (`ksm.0`) on game start and repeatedly reapplies leader fixes on modification complete, level-up, and monthly pulse.
- `common/on_actions/05_bgbn_exploration_on_actions.txt` starts exploration content from `on_entering_system_fleet` and `on_survey_planet`.

### Initialization and empire gating

Most content is gated behind the custom authority / country flags rather than being globally available.

- `common/governments/authorities/11_ksm_authorities.txt` defines the custom authority `auth_radiant_harmony`.
- `events/ksm_events.txt` is the main bootstrap file:
  - `bgbn_start.1` grants the `poppinparty` country flag to empires using `auth_radiant_harmony`.
  - `ksm.0` performs the main setup for player empires with that flag, creates the custom species target, and calls scripted setup effects such as `create_ksm`, `create_ars`, `create_saaya`, `create_tae`, `create_rimi`, and `create_asuka`.
  - `ksm.2` is a recurring normalization pass that reapplies leader portraits, ages, and cleanup for multiple band-specific leader flags.

In practice, `poppinparty` is the main feature gate. Before changing events or content triggers, check whether they rely on `has_country_flag = poppinparty` or related `have_*` / role flags.

### Content organization

`common/` holds data definitions that Stellaris loads directly:

- `common/governments/` defines the custom authority and civics.
- `common/traits/`, `common/pop_jobs/`, `common/buildings/`, `common/starbase_buildings/`, `common/strategic_resources/`, `common/relics/`, `common/technology/`, and related folders define gameplay objects.
- `common/scripted_effects/` contains reusable creation / repair logic for specific bands and characters. These effects are heavily reused by startup and event files.
- `common/situations/bgbn_situations.txt` defines the `situation_Reconstruction` and `situation_Explore` situations; the corresponding event logic lives in `events/bgbn_situation_events.txt`.
- `common/solar_system_initializers/` defines custom systems used by the mod. `ksm_sol_initializers.txt` contains the custom Sol/home system setup, while `deepred_event_initializers.txt` defines special story systems generated by event chains.
- `common/archaeological_site_types/bgbn_deepred_arc_sites_1.txt` defines archaeology sites, while their stage events are implemented in `events/bgbn_ancient_relics_arcsite_events.txt`.
- `common/on_actions/` is the glue that activates everything.

`events/` contains the interactive logic:

- `events/ksm_events.txt` bootstraps the mod and leader state.
- `events/popy_events.txt` handles the Popy role-selection / role-switch event flow.
- `events/bgbn_situation_events.txt` contains the event-side progression and rewards for the situations defined in `common/situations/`.
- `events/bgbn_all_space_exploration_events.txt` implements a large exploration event chain driven by fleet/system/ship triggers plus event-chain counters.
- `events/bgbn_ancient_relics_arcsite_events.txt` drives the archaeology storyline; country events create sites, fleet archaeology events provide stage text/results.
- Other `events/*.txt` files cover civics, deposits, agreements, live events, traditions, and band-specific content.

### Event-chain patterns used in this repo

A few patterns recur across the mod:

- **Authority -> country flag -> content unlock**: the custom authority grants `poppinparty`, and most custom content checks that flag.
- **Country event bootstraps scripted effects**: startup events do minimal orchestration and delegate actual leader/species creation to `common/scripted_effects/*.txt`.
- **Recurring repair events**: portrait and leader consistency is maintained by repeatedly firing `ksm.2` from several on_actions. If a leader visual/state bug appears, inspect both the triggering on_action and the relevant scripted effect.
- **Situation split across data + events**: situation definitions in `common/situations/` only define stages/progress hooks; real rewards and branching are in `events/bgbn_situation_events.txt`.
- **Archaeology split across site defs + event stages**: archaeology site metadata lives in `common/archaeological_site_types/`, but stage text/progression/rewards are in `events/bgbn_ancient_relics_arcsite_events.txt`.
- **Exploration progression via event-chain counters**: `events/bgbn_all_space_exploration_events.txt` uses event-chain counters and country flags to unlock milestones.
- **Global/event targets for special worlds**: special planets/systems are frequently saved as event targets in initializers and then modified later by events.

### Assets and localisation

- `localisation/english/` and `localisation/simp_chinese/` contain the strings for events, names, civics, deposits, situations, etc. Most gameplay edits need matching localisation updates.
- `gfx/interface/` contains icons for authorities, civics, traits, resources, traditions, subject perks, and related UI assets.
- `gfx/event_pictures/` and other `gfx/` folders provide event art and presentation assets.
- There are `.dds` and a small number of `.png` assets in the repo; no `.gui` files were found.

## Working guidance for future edits

- Treat this as a Paradox script/data repo, not a conventional application codebase.
- When changing behavior, search both the data definition under `common/` and the event logic under `events/`; many features are split across both.
- Before renaming or deleting a flag / event ID / scripted effect, grep the whole repo. Cross-file coupling is high.
- If you change gameplay text keys or add new content, update localisation alongside the script change.
- If a change touches leader setup or portraits, inspect both `events/ksm_events.txt` and the relevant `common/scripted_effects/z_*_effects.txt` file.
- If a change touches special systems, archaeology, or Earth deposits, inspect the corresponding initializer/event pair rather than only one side of the implementation.
